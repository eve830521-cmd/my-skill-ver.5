Q1. ai_prep_digest.md 생성과 Phase 1~3 작성을 분리할까, Orchestrator (Neon)로 한 번에 할까?

🏆 [베스트안] 2-Step 분리 + 10초 체크포인트 퀄리티·토큰 모두 1위

구조: [Step 1] Hydrogen High (복잡공시는 Neon Med)로 prep ➔ 10초 숫자 확인 ➔ 🆕 새 창 [Step 2] Neon High로 Phase 1~3 + build

  • 왜 퀄리티가 가장 높은가? ① 1단계 직후 사용자가 FCF·순차입금·비영업자산·가동률·매도시그널 6~8개 핵심 SSOT 파라미터를 10초 만에 검수해 GIGO(오염 입력)를 원천 차단합니다. ② 2단계 Neon (High)는 DART API raw JSON과 PDF 검색 로그 찌꺼기 없이 100% 깨끗한 컨텍스트로 오직 ai_prep_digest.md 1개만 읽고 추론합니다.
  • 왜 토큰도 가장 적게 드는가? 무거운 DART 다중 조회(5~10턴)를 Hydrogen 독립 풀로 넘기고, Neon (High)는 단 5~6턴(읽기 1 + 쓰기 4 + 빌드 1) + static_cache_prefix.md 95% 캐시 히트로 완결합니다.
  • 안전장치: 2단계 프롬프트에 "SSOT 수치에 명백한 회계 오류 발견 시 1회 보정 후 진행" 문구를 넣어 이중 방어!

🎼 [대안 A] Orchestrator (Neon) 원샷 통합 편의성 1위 · 토큰 1.5~2x

구조: 🆕 새 창 Orchestrator (Neon)에 한 줄 명령 ➔ 내부 서브에이전트 탐색 ➔ prep ➔ Phase 1~3 ➔ build 자동 완결

  • 장점: 사용자가 중간에 모델을 바꾸거나 새 창을 열 필요 없이 명령 1줄만 던지고 다른 일을 볼 수 있습니다. 내부적으로 탐색용 서브에이전트를 띄워 메인 컨텍스트 오염을 어느 정도 막아줍니다.
  • 단점 (솔직한 트레이드오프): ① 내부 계획 수립·서브에이전트 호출·결과 검증 왕복 때문에 단일 Neon (High) 2-Step 대비 토큰 소모가 1.4~2.0배 증가합니다. ② prep 직후 사용자가 SSOT 핵심 가정(SOTP 범위·Owner FCF·침투율)을 중간 확인하지 않고 Phase 1~3까지 끝까지 달려버리므로, 가정이 어긋나면 리빌드 비용이 2배로 듭니다.
  • 최적 용도: 신규 기업 최초 세팅+분석 원샷 위임, 3~5개 기업 일괄 점검, my-skill 파이프라인 코드 수정.

Q2. 명령을 분리할 때 대화창을 새로 만들어야 할까? (🆕 새 대화창 vs 🔗 같은 대화창 절대 기준표)
